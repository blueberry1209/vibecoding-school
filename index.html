차시 01

출발점과 도구 준비

24차시의 결과물과 작업 순서를 이해하고 Windows 개발 환경을 확인한다.

용어 미리보기npm

JavaScript 프로젝트의 패키지와 실행 명령을 관리하는 도구입니다.

실습 장면: npm install, npm run dev, npm run build를 실행합니다. · 확인 질문: package.json의 scripts에는 어떤 명령이 있는가?
핵심 개념바이브코딩, 브라우저, 터미널, 편집기
오늘의 비유요리 전에 도마와 칼을 꺼내듯, 코딩도 도구를 먼저 한자리에 둔다.
완료 기준세 명령 모두 버전 숫자를 출력하고, VS Code의 터미널에서 같은 결과가 나오는지 확인한다.

실습 단계

  1. Chrome에서 VS Code 설치 페이지와 Node.js LTS 설치 페이지를 확인한다.
  2. PowerShell을 열고 `node -v`, `npm -v`, `git --version`을 차례로 실행한다.
  3. VS Code에서 폴더를 하나 열고 통합 터미널을 켠다.
복사해 실행하거나 파일에 붙여 넣을 코드
node -v
npm -v
git --version
코드 해설
버전 명령은 설치 여부를 묻는 가장 짧은 진단이다. 숫자가 출력되면 해당 도구를 호출할 수 있다.

오류 해결

증상해결 순서
명령을 찾을 수 없음Node.js 또는 Git을 다시 설치한 뒤 PowerShell을 새로 연다.
npm 실행 정책 오류`npm.cmd`로 실행하거나 현재 PowerShell 창에서만 실행 정책을 조정한다.
한글 경로 문제처음 프로젝트는 영문 폴더명으로 만들어 경로 변수를 줄인다.

개선 아이디어와 응용

차시 02

프로젝트 폴더와 Git 시작

작업 폴더를 만들고 Vite 프로젝트를 실행하며 첫 저장 지점을 만든다.

용어 미리보기package.json

프로젝트 이름·의존성·실행 명령을 적는 설정 파일입니다.

실습 장면: Vite 개발 서버와 빌드 명령을 확인합니다. · 확인 질문: 새 라이브러리를 추가하면 어느 파일이 바뀌는가?
핵심 개념프로젝트, npm, Git 저장소, 커밋
오늘의 비유작업 폴더는 수업용 바인더이고, 커밋은 바인더에 꽂는 날짜별 복사본이다.
완료 기준브라우저에서 Vite 기본 화면이 보이고, 프로젝트 폴더에 `src`, `index.html`, `package.json`이 있는지 확인한다.

실습 단계

  1. PowerShell에서 `npm create vite@latest instructor-home -- --template vanilla`를 실행한다.
  2. `cd instructor-home`, `npm install`, `npm run dev` 순서로 실행한다.
  3. 다른 터미널에서 `git init`, `git add .`, `git commit -m "chore: start project"`를 실행한다.
복사해 실행하거나 파일에 붙여 넣을 코드
npm create vite@latest instructor-home -- --template vanilla
cd instructor-home
npm install
npm run dev
코드 해설
Vite는 개발 서버와 기본 파일을 만들어 주고, Git은 변경 이력을 저장할 준비를 한다.

오류 해결

증상해결 순서
npm create가 멈춤커서가 입력을 기다리는지 확인하고 안내 질문에 기본값으로 응답한다.
포트 사용 중터미널이 제시한 다른 포트 주소를 열거나 기존 개발 서버를 종료한다.
git은 내부 또는 외부 명령이 아님Git 설치 후 VS Code와 PowerShell을 다시 시작한다.

AI 협업 프롬프트

복사 가능한 프롬프트
학생이 폴더와 Git을 처음 만지는 장면을 비유로 설명해 줘. 반드시 복사할 PowerShell 명령과 각 명령의 확인 결과를 함께 써 줘.

개선 아이디어와 응용

  • `README.md`에 오늘 실행한 명령과 확인 결과를 기록한다.
  • 실습 중 중요한 순간마다 커밋을 남기는 ‘중간 저장’ 규칙을 만든다.
차시 03

HTML 뼈대와 의미 있는 구조

페이지를 소개, 프로그램, 실적, 문의 영역으로 나누고 시맨틱 HTML을 사용한다.

용어 미리보기HTML

웹 페이지의 내용과 구조를 적는 언어입니다.

실습 장면: index.html에서 제목·문단·버튼·폼을 만듭니다. · 확인 질문: 문서의 내용과 구조를 담당하는 파일은 무엇인가?
핵심 개념HTML 요소, section, heading, nav, form
오늘의 비유HTML은 교실의 좌석 배치도다. 같은 목적의 활동이 어디에 놓였는지 먼저 읽힌다.
완료 기준브라우저에서 ‘강사 소개’가 보이고 주소 뒤에 `#about`을 붙였을 때 해당 영역으로 이동한다.

실습 단계

  1. VS Code에서 `index.html`을 열고 `lang="ko"`와 제목을 확인한다.
  2. `header`, `main`, `section`, `footer`를 배치한다.
  3. 각 section에 한 개의 h2와 짧은 설명을 추가하고 저장한다.
복사해 실행하거나 파일에 붙여 넣을 코드
<main>
  <section id="about" aria-labelledby="about-title">
    <h2 id="about-title">강사 소개</h2>
    <p>교실의 질문을 작동하는 경험으로 바꿉니다.</p>
  </section>
</main>
코드 해설
id는 링크와 JavaScript가 찾을 주소이고, aria-labelledby는 보조공학에 section의 제목을 알려 준다.

오류 해결

증상해결 순서
화면에 태그가 글자로 보임태그를 `index.html` 안에 넣었는지, `.txt` 확장자가 아닌지 확인한다.
링크가 이동하지 않음href의 `#about`과 section의 id 철자가 같은지 비교한다.
제목 계층이 어색함페이지 제목은 h1 하나, 주요 영역은 h2로 정리한다.

AI 협업 프롬프트

복사 가능한 프롬프트
학생에게 시맨틱 HTML을 ‘교실 배치도’로 설명하고, 강사 홈페이지에 필요한 4개 section을 설계하게 하는 활동지를 만들어 줘.

개선 아이디어와 응용

  • 프로그램 카드 하나를 `article`로 바꾸어 반복 콘텐츠의 단위를 분명히 한다.
  • 문의 form에 label을 연결해 키보드와 스크린리더가 입력 목적을 알 수 있게 한다.
차시 04

색상 토큰과 카드 스타일

교실 환경에 맞는 코랄·아쿠아·빈티지 그레이프·페일 앰버 색상 토큰을 만들고 반복 스타일을 줄인다.

용어 미리보기CSS

색상, 글꼴, 여백, 배치를 정하는 스타일 규칙입니다.

실습 장면: src/style.css에서 팔레트와 반응형 레이아웃을 조정합니다. · 확인 질문: 카드의 색과 간격을 바꾸려면 어디를 수정하는가?
핵심 개념CSS 변수, 색상 대비, border-radius, spacing
오늘의 비유토큰은 미술 시간의 색상표다. 이름을 붙여 두면 같은 색을 다시 찾기 쉽다.
완료 기준파치먼트 배경 위에서 빈티지 그레이프 글자가 읽히며, 카드 모서리가 12px로 보이는지 확인한다.

실습 단계

  1. `src/style.css`에 `:root` 변수를 만든다.
  2. body, card, button에 변수를 적용한다.
  3. 브라우저에서 배경과 본문 대비를 확인하고 한 가지 모서리 값으로 통일한다.
복사해 실행하거나 파일에 붙여 넣을 코드
:root {
  --sand: #F2EFEA;
  --charcoal: #403d58;
  --accent: #FC7753;
  --radius-card: 12px;
  --space-medium: 24px;
}
.card { border-radius: var(--radius-card); background: #FFFFFF; }
코드 해설
변수는 이름을 가진 값이다. 디자인을 바꿀 때 여러 선택자를 찾아다니지 않고 변수 한 곳을 바꾼다.

오류 해결

증상해결 순서
변수가 적용되지 않음변수 이름 앞에 `--`가 있는지, 사용하는 곳에 `var()`가 있는지 확인한다.
글자가 흐림배경과 글자 대비를 높이고 본문 글자 크기를 16px 이상으로 둔다.
카드가 검게 보임배경 선언이 유효한 hex 값인지 확인하고 브라우저를 새로 고친다.

AI 협업 프롬프트

복사 가능한 프롬프트
파치먼트 배경과 빈티지 그레이프 본문, 코랄·아쿠아 포인트를 쓰는 교육용 홈페이지의 CSS 토큰을 설계하고, 각 토큰이 쓰이는 위치를 설명해 줘.

개선 아이디어와 응용

  • 학교 브랜드 색을 포인트 색으로 바꾸되 본문 대비와 버튼의 가독성을 먼저 검사한다.
  • 다크 모드를 추가할 때도 변수만 교체해 본문 구조를 유지한다.
차시 05

반응형 레이아웃

프로젝터·크롬북·태블릿 화면에서 같은 콘텐츠가 자연스럽게 흐르도록 Grid와 미디어 쿼리를 사용한다.

용어 미리보기반응형 웹

화면 폭에 따라 배치와 크기가 자연스럽게 바뀌는 설계입니다.

실습 장면: 390·768·1280px에서 카드와 버튼이 깨지지 않는지 확인합니다. · 확인 질문: 모바일에서 가로 스크롤이 생기는 이유는 무엇인가?
핵심 개념CSS Grid, Flexbox, breakpoint, minmax
오늘의 비유책상을 접었다 펴는 것처럼, 작은 화면에서는 열을 줄이고 간격을 다시 배치한다.
완료 기준세 화면 크기에서 가로 스크롤이 없고 카드 순서가 자연스러운지 확인한다.

실습 단계

  1. 프로그램 카드 영역을 3열 Grid로 만든다.
  2. 800px 이하에서 1열로 바꾸고 navigation을 줄인다.
  3. Chrome 개발자 도구의 기기 모드에서 390px, 768px, 1280px을 확인한다.
복사해 실행하거나 파일에 붙여 넣을 코드
.card-grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 16px;
}
@media (max-width: 800px) {
  .card-grid { grid-template-columns: 1fr; }
}
코드 해설
Grid는 같은 폭의 반복 콘텐츠에 적합하다. 미디어 쿼리는 화면 조건이 달라졌을 때 레이아웃 규칙을 바꾼다.

오류 해결

증상해결 순서
카드가 화면 밖으로 나감고정 px 폭 대신 `1fr`과 `minmax`를 사용하고 부모의 max-width를 확인한다.
모바일에서 글자가 작음본문의 최소 크기를 유지하고 제목은 clamp로 조절한다.
가로 스크롤 발생개발자 도구에서 폭을 넘는 요소를 찾아 `width: 100%`를 적용한다.

AI 협업 프롬프트

복사 가능한 프롬프트
초중고 교실 프로젝터, 크롬북, 태블릿을 모두 고려한 반응형 카드 레이아웃을 제안하고 각 breakpoint에서 확인할 질문을 써 줘.

개선 아이디어와 응용

  • 프로젝터용 발표 모드에서는 카드 수를 2개로 줄이고 설명을 크게 보이게 한다.
  • 학생이 직접 화면 폭을 바꾸며 ‘레이아웃이 무너지는 지점’을 관찰 일지로 기록한다.
차시 06

SVG 아이콘과 접근성

무거운 아이콘 라이브러리 없이 currentColor를 쓰는 24x24 SVG 아이콘을 직접 넣는다.

용어 미리보기SVG

선과 도형을 코드로 표현하는 확대 가능한 이미지 형식입니다.

실습 장면: 아이콘과 빈 상태 안내 그림을 외부 라이브러리 없이 넣습니다. · 확인 질문: SVG 색상을 currentColor로 연결하면 무엇이 좋아지는가?
핵심 개념inline SVG, currentColor, aria-hidden, focus-visible
오늘의 비유아이콘은 표지판이다. 같은 색을 따라가고, 표지판만으로 의미를 강요하지 않는다.
완료 기준아이콘 색이 버튼 색과 함께 바뀌고 Tab 키로 버튼에 초점이 보이는지 확인한다.

실습 단계

  1. 24x24 viewBox의 SVG 하나를 복사한다.
  2. stroke를 `currentColor`로 두고 버튼의 color를 상속받게 한다.
  3. 아이콘 옆에 텍스트를 두고 키보드 focus-visible 상태를 확인한다.
복사해 실행하거나 파일에 붙여 넣을 코드
<svg viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.8" aria-hidden="true">
  <path d="M5 12h14M13 6l6 6-6 6" stroke-linecap="round" stroke-linejoin="round"/>
</svg>
코드 해설

비동기 상태와 중복 클릭 방지

제출 순간 버튼을 잠그고 진행 문구·스피너·완료·실패 상태를 화면에 보여 준다.

용어 미리보기async/await

비동기 작업이 끝날 때까지 읽기 쉬운 순서로 기다리는 문법입니다.

실습 장면: fetch 결과를 받은 뒤 JSON을 읽고 화면에 표시합니다. · 확인 질문: await가 빠지면 결과를 바로 사용할 수 있는가?
핵심 개념async/await, disabled, loading state, status
오늘의 비유엘리베이터 버튼을 계속 눌러도 더 빨리 오지 않는다. 요청 중에는 상태를 보여 주고 한 번만 받는다.
완료 기준버튼을 연속 클릭해도 요청 중에는 한 번만 눌리고, 완료 후 기본 문구로 돌아오는지 확인한다.

실습 단계

  1. submit 이벤트에서 preventDefault를 호출한다.
  2. 버튼 disabled와 loading class를 켠다.
  3. finally에서 버튼을 되돌리고 status에 결과를 남긴다.
복사해 실행하거나 파일에 붙여 넣을 코드
async function submitForm() {
  button.disabled = true;
  button.querySelector(".button-label").textContent = "전송 중...";
  try {
    await fetch("/api/contact", { method: "POST" });
    status.textContent = "문의가 접수되었습니다.";
  } finally {
    button.disabled = false;
  }
}
코드 해설
try는 성공 경로, catch는 실패 경로, finally는 어떤 결과에도 실행되는 정리 작업이다.

오류 해결

증상해결 순서
버튼이 계속 활성화disabled를 boolean으로 설정했는지 확인하고 상태 클래스와 선택자를 점검한다.
실패해도 ‘완료’로 보임response.ok를 검사하고 catch에서 실패 문구를 설정한다.
스피너가 사라지지 않음finally에서 loading class를 제거한다.

용어 미리보기fetch

브라우저나 서버에서 네트워크 요청을 보내는 함수입니다.

실습 장면: GitHub·AI·문의 API에 GET 또는 POST 요청을 보냅니다. · 확인 질문: 요청 전후에 loading 상태를 어떻게 보여 주는가?
핵심 개념fetch, JSON, HTTP status, empty state
오늘의 비유도서관 목록을 매번 베껴 쓰지 않고, 목록 서비스에 최신 카탈로그를 요청한다.

실습 단계

  1. GitHub 사용자 이름 설정값을 만든다.
  2. fetch 후 response.ok를 확인하고 JSON을 읽는다.
  3. fork를 제외하고 최신 저장소 3개만 카드로 표시한다.
복사해 실행하거나 파일에 붙여 넣을 코드
const response = await fetch(
  `https://api.github.com/users/${username}/repos?sort=updated&per_page=3`
);
if (!response.ok) throw new Error("github-request-failed");
const repositories = await response.json();
renderProjects(repositories.filter((repo) => !repo.fork));
코드 해설
URL의 username을 encodeURIComponent로 안전하게 넣고, HTTP 응답이 200번대가 아니면 실패로 처리한다.

차시 15

Vercel 서버 함수와 안전한 API 프록시

브라우저에 API 키를 노출하지 않고 Vercel Function에서 외부 AI API를 호출한다.

용어 미리보기Serverless Function

서버를 직접 관리하지 않고 필요할 때 실행되는 서버 코드입니다.

실습 장면: api/ask-ai.js와 api/contact.js가 Vercel에서 실행됩니다. · 확인 질문: 함수에서 검증해야 할 입력과 환경 변수는 무엇인가?
핵심 개념serverless function, POST, environment variable, secret
오늘의 비유교실 창구에서 신청서를 받고, 열쇠가 필요한 서류실 업무는 뒤에서 처리한다.
완료 기준개발자 도구 Network 탭에서 요청 body에 API 키가 없고, 키가 없는 데모 모드도 오류 화면을 만들지 않는지 확인한다.

실습 단계

  1. `api/ask-ai.js` 파일을 만든다.
  2. POST body의 question을 검증한다.
  3. `process.env.OPENAI_API_KEY`를 사용해 외부 API를 호출하고 답만 반환한다.
복사해 실행하거나 파일에 붙여 넣을 코드
export default async function handler(request, response) {
  if (request.method !== "POST") return response.status(405).end();
  const { question } = request.body || {};
  if (!question?.trim()) return response.status(400).json({ error: "질문 필요" });
  const upstream = await fetch("https://api.openai.com/v1/responses", {
    method: "POST",
    headers: { Authorization: `Bearer ${process.env.OPENAI_API_KEY}` },
  });
  return response.status(200).json(await upstream.json());
}
코드 해설
브라우저 JavaScript에는 비밀값을 넣지 않는다. 서버 함수가 요청을 받아 환경 변수를 사용하고, 브라우저에는 필요한 결과만 돌려준다.

오류 해결

증상해결 순서
401 인증 오류Vercel 환경 변수 이름이 정확한지, 배포 환경에 값이 저장됐는지 확인한다.
500 함수 오류함수 로그와 요청 body 구조를 확인하고 민감한 값을 로그로 출력하지 않는다.
브라우저에 키가 보임`src` 파일에서 키를 제거하고 `.env`는 Git에 커밋하지 않는다.

용어 미리보기Prompt

오늘의 비유AI에게 ‘도와줘’라고 말하는 대신, 학년·목표·제약이 적힌 수업 의뢰서를 건넨다.

실습 단계

  1. question textarea를 만든다.
  2. 서버에서 한국어·3단계 활동·확인 질문 규칙을 지시한다.
  3. 응답을 status 영역에 표시하고 긴 문장은 충분한 줄 높이로 보여 준다.
복사해 실행하거나 파일에 붙여 넣을 코드
const payload = {
  model: process.env.OPENAI_MODEL || "gpt-4.1-mini",

코드 해설
instructions는 역할과 출력 규칙, input은 사용자의 실제 상황이다. 둘을 분리하면 같은 품질 기준을 반복해서 적용할 수 있다.

용어 미리보기Webhook

실습 장면: 문의 내용을 지정된 자동화 서비스로 전송합니다. · 확인 질문: 전달할 개인정보를 최소화했는가?
핵심 개념payload, validation, webhook, privacy
오늘의 비유우편함에 넣기 전 주소와 봉투를 확인하고, 정해진 수신함으로 전달한다.
완료 기준환경 변수가 없을 때도 데모 성공 메시지가 나오고, 실제 webhook을 설정하면 응답 상태가 성공으로 돌아오는지 확인한다.

실습 단계

  1. name·email·message의 필수 여부를 검사한다.
  2. trim으로 앞뒤 공백을 제거한 safePayload를 만든다.
  3. CONTACT_WEBHOOK_URL이 없으면 데모 접수, 있으면 webhook POST를 실행한다.
복사해 실행하거나 파일에 붙여 넣을 코드
const safePayload = {
  name: payload.name.trim(),
  email: payload.email.trim(),
  topic: String(payload.topic || "기타"),
  message: payload.message.trim(),
};
await fetch(process.env.CONTACT_WEBHOOK_URL, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(safePayload),
});
코드 해설
서버는 입력을 그대로 전달하지 않고 필요한 필드만 골라 safePayload를 만든다. webhook은 이메일·자동화 서비스·데이터베이스로 확장할 수 있다.

증상해결 순서

function renderProjects(repositories) {
  const target = document.querySelector("#github-projects");
  target.setAttribute("aria-busy", "false");
  if (!repositories.length) {
    target.innerHTML = emptyState("표시할 공개 저장소가 없습니다. GitHub 사용자 이름을 설정해 보세요.");
    return;
  }
  target.innerHTML = repositories.map((repo) => `
    <a class="project-card" href="${repo.html_url}" target="_blank" rel="noreferrer">
      <span class="program-number">Repository</span><h3>${repo.name}</h3><p>${repo.description || "설명이 아직 없습니다."}</p>
      <span class="project-meta"><span>${repo.language || "Web"}</span><span>Star ${repo.stargazers_count}</span></span>
    </a>`).join("");
}

async function loadGithubProjects() {
  try {
    if (siteConfig.githubUsername === "YOUR_GITHUB_USERNAME") throw new Error("username-not-configured");
    const response = await fetch(`https://api.github.com/users/${encodeURIComponent(siteConfig.githubUsername)}/repos?sort=updated&per_page=3`);
    if (!response.ok) throw new Error("github-request-failed");
    const repositories = await response.json();
    renderProjects(repositories.filter((repo) => !repo.fork));
  } catch {
    renderProjects([]);
  }
}

export default async function handler(request, response) {

      headers: { "Content-Type": "application/json", Authorization: `Bearer ${process.env.OPENAI_API_KEY}` },

        model: process.env.OPENAI_MODEL || "gpt-4.1-mini",
        instructions: "당신은 초중고 교사를 돕는 수업 설계 조교입니다. 한국어로 답하고, 바로 실행할 수 있는 3단계 활동과 확인 질문 1개를 제안하세요.",

  } catch {
    return response.status(500).json({ error: "AI 요청 중 오류가 발생했습니다." });
  }
}

export default async function handler(request, response) {
  if (request.method !== "POST") return response.status(405).json({ error: "POST 요청만 사용할 수 있습니다." });
  const payload = request.body || {};
  const required = ["name", "email", "message"];
  if (required.some((key) => typeof payload[key] !== "string" || !payload[key].trim())) {
    return response.status(400).json({ error: "이름, 이메일, 문의 내용을 확인해 주세요." });
  }

  const safePayload = { name: payload.name.trim(), email: payload.email.trim(), topic: String(payload.topic || "기타"), message: payload.message.trim(), createdAt: new Date().toISOString() };
  if (!process.env.CONTACT_WEBHOOK_URL) {
    return response.status(200).json({ ok: true, mode: "demo", message: "데모 접수 완료" });
  }
  try {
    const webhook = await fetch(process.env.CONTACT_WEBHOOK_URL, { method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify(safePayload) });
    if (!webhook.ok) return response.status(502).json({ error: "문의 전달에 실패했습니다." });
    return response.status(200).json({ ok: true, mode: "webhook" });
  } catch {
    return response.status(500).json({ error: "문의 전달 중 오류가 발생했습니다." });
  }
}
